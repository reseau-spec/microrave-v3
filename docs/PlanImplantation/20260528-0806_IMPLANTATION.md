## CONTRAINTE ARCHITECTURALE CRITIQUE — À LIRE AVANT TOUT

**Le runtime Deno cloud Base44 est un environnement fermé.**

Les fonctions dans `codeBase44_v3/base44/functions/*/entry.ts` sont
déployées dans le cloud Base44. Elles n'ont accès qu'au contenu de
`codeBase44_v3/`. Elles ne peuvent PAS faire :

```typescript
// IMPOSSIBLE en production Base44 :
import { transitionEngagement } from '../../../src/core/transitionEngagement.js';
```

`src/` n'existe pas dans le runtime cloud. Ce pattern était documenté
comme aspiration dans `base44-adapter.js` mais n'a jamais été validé
en déploiement réel. Ne pas l'implémenter tel quel.

**Ce que le runtime Deno Base44 CAN faire :**
- `import { createClientFromRequest } from 'npm:@base44/sdk@0.8.25'`
- Imports relatifs depuis `codeBase44_v3/` uniquement.
- Imports npm: vers des packages publics.

**L'architecture correcte :**
La logique métier canonique vit dans `src/`. Les fonctions Deno sont
des **couches minces** qui : authentifient, valident l'input,
appellent le runtime Base44 pour lire/écrire des entités, et
délèguent les décisions à des **modules partagés dans `codeBase44_v3/`**
qui sont des re-exports ou des ponts vers la logique src/.
